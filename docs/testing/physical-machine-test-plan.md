## Recording the evidence in the software (Machine test dialog)
1. Export the DST from the design you will stitch. The status chip in the status bar (bottom) shows **PENDING** until a record exists for this exact file (SHA-256).
2. Click the chip -> **Machine test**: it lists the checklist, shows the DST checksum, and takes the record: operator, design name + version, machine model, fabric, stabiliser, needle, thread, hoop, stitch count, speed, thread breaks, skipped stitches, puckering (0-3), worst registration gap (mm), jumps/trims result, final inspection (pass / pass with notes / fail), notes.
3. The record is stored in the server folder `evidence/` as `ev_<id>.json`, sealed with its own SHA-256 (`record_sha256`); it can be exported / imported as JSON (an edited record is refused).
4. Status rules: **INCOMPLETE** while a required field is missing; **FAILED** if final inspection = fail; **PASSED_WITH_NOTES**; **PASSED** only with every field filled, inspection = pass and a record checksum equal to the current DST. **STALE**: the design was tested before but the DST has changed since - the old result no longer applies.
5. The software never creates a result itself. This repository contains **no** evidence records (a test enforces it). API: `GET /api/evidence?sha=`, `GET /api/evidence/records`, `GET /api/evidence/checklist`, `POST /api/evidence`, `POST /api/evidence/import`.
